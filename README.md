# Research Weekly v0.3a.1｜学术研究周报

这是无需构建的静态网站，已通过 GitHub Pages 部署。公开周报从仓库 JSON 读取；手动报告和收藏保存在当前浏览器，不会自动上传或跨设备同步。

## 预览

1. 在项目目录启动本地 HTTP 服务器，再用 Chrome 或 Edge 打开网站；不要用双击 HTML 的方式验收公开 JSON 读取。
2. 安装 Python 后运行 `python -m http.server 8000 --bind 127.0.0.1`，访问 `http://127.0.0.1:8000/`。Windows 也可使用 `py -m http.server 8000 --bind 127.0.0.1`；Ctrl+C 停止。公开 JSON 和外部链接需要可用的网络连接。
3. 修改文件后，在浏览器按 Ctrl+R 刷新。原本已使用本项目的用户应尽量保留原文件位置和同一个浏览器；不同文件路径、浏览器和线上域名的数据可能相互独立。
4. 首次升级后先下载 JSON 备份。文件浏览模式下浏览器对本地存储的行为可能有差异；不要依靠无痕窗口长期保存。

## 文件结构

- `index.html`：页面结构、管理菜单、阅读区和周报编辑表单。
- `styles.css`：白色布局、折叠导航、响应式阅读面板、每周强调色。
- `app.js`：显示、筛选、搜索、编辑、收藏、备份及兼容逻辑。
- `sample.js`：明确标记为示例的演示资料；保留旧示例条目 ID。
- `check.cjs`：可选的 Node.js 自动检查，不是网页运行依赖。
- 开发说明 Markdown 和视觉参考 PNG：原始需求资料，未修改。

## 新版功能

- 左侧折叠导航：主页、档案、收藏；放大镜进入全站搜索，底部为关于本站。
- 主页显示所选周次、日期范围、总报告和当周一句话研究动态。装饰插图仅出现在总报告卡片，可按周配置原创 SVG 或其他本地图片。
- 首页“主题筛选”可同时勾选多个标签，匹配其中任一标签；选择“全部”清空筛选。标签在列表隐藏，在详情显示。
- 点击信息或总报告，在右侧打开学术文档阅读区；手机全屏。支持收藏、复制链接、自动目录、目录跳转、阅读进度和 Escape 关闭。
- 档案按发布日期倒序，每期一条；点击后回到该期总报告和信息列表。主页默认显示最新正式公开周报；没有正式公开周报时保留最新本地报告或演示内容。
- 搜索跨所有期数，包含总报告正文、独立信息正文及标签；按 `/` 快速进入搜索。
- 右上角依次为上传 / 导入、下载 JSON、相关链接。链接面板可关闭、滚动，外部链接一律在新标签打开。
- 主题强调色按 ISO 周次在淡紫、灰蓝、鼠尾草绿、浅杏之间轮换，背景保持白色。

## 添加或编辑周报

1. 点击右上角“上传 / 导入”，选择“新建 / 粘贴周报”。
2. 填写标题、报告日期、简短综述和完整总报告。
3. 点击“添加一条信息”，分别填写一句话动态、详情、逗号分隔的多个标签，可选发生日期与来源说明。重复添加即可；也允许只存总报告。
4. 保存后进入该期。需要修改时，在该期选择上传菜单内“编辑当前周报”。演示资料不能直接编辑。
5. 详情按发生日期倒序排列；没填发生日期时使用报告日期，不生成虚构时间。

正文使用轻量文本格式，不执行 HTML：

```text
## 研究动态综述
这里写正文。

### 证据与讨论
- 第一项证据
- 第二项证据

> 一段引用

[原文链接](https://example.com/)
```

有至少两个标题时显示目录。支持普通 HTTP/HTTPS 链接，不支持任意 HTML、图片、完整 Markdown 或自动文献解析。

## 旧数据与备份

继续使用原存储键 `rw-reports-v1`、`rw-bookmarks-v1`，不在首次加载时重写数据。旧条目 ID 不变，已有收藏继续可用。

旧版“完整周报”条目的全文会作为总报告正文读取，原条目仍保留，避免失去收藏入口。其他旧报告没有独立总文时，以原条目内容组合为兼容阅读正文，原对象不会因读取而被覆盖。编辑保存时才写入扩展字段。

新增周报用 `body` 保存总报告，用 `entries` 保存独立信息；条目支持 `tags`、可选 `date` 和 `source`。导出继续采用 `research-weekly-v1` 标识，同时增加 `version: 2`，保留 reports 与 bookmarks。新版支持恢复原 v1 备份和新版备份；应使用新版网页读取新版备份。

恢复前检查结构并明确确认，因为恢复会替换当前报告与收藏。请先下载当前备份。恢复写入失败时尝试回滚原存储；存储不可读时阻止后续写入。浏览器配额、隐私模式或系统故障仍可能影响保存，JSON 文件是重要备份。

复制链接只包含报告及条目 ID，不包含正文。本地文件链接不是公开分享网址，接收方需要有同一份数据和可访问的网站；换设备请手动导出、导入 JSON。

## 手动检查清单

1. 点击左上折叠按钮，再展开；悬停检查图标提示，用 Tab 和 Enter 访问导航与工具。
2. 主页展开“主题筛选”，选择两个标签，检查匹配任一标签的结果；选“全部”恢复。
3. 打开研究信息，检查详情、标签及日期；关闭后检查筛选和列表位置保留。
4. 点击“阅读完整报告”，打开目录，选择一个标题，检查正文跳转及目录自动关闭；滚动检查顶部细进度条。
5. 收藏一条信息，进入收藏再打开；取消收藏后检查列表更新。刷新检查收藏仍在。
6. 进入档案，点击一期，检查总报告和当期信息；新建不同日期的测试周报，验证排序。
7. 用左侧放大镜搜索旧期正文中的词，确认能找到旧期资料；主页没有第二个搜索框。
8. 新建一份“测试周报”，总文放两个 `##` 标题，添加两条不同日期、多标签的独立信息。保存、刷新、重新打开并编辑。
9. 下载 JSON，检查文件中 reports、bookmarks、body 和 entries；恢复前先备份，测试恢复；也可以恢复原 v1 备份。
10. 粘贴 `<img src=x onerror=alert(1)>` 或 `<script>` 等测试文字，应只显示文字，不执行。外部链接应新开标签。
11. 缩窄浏览器到手机尺寸：导航默认在首次加载时收起，阅读面板全屏，上传与备份工具仍可用。
12. 打开相关链接面板，检查新标签访问、关闭和窗口较矮时的滚动。

自动检查：安装了 Node.js 的开发环境可运行 `node check.cjs`。该检查使用隔离的模拟 DOM 和存储，不接触真实浏览器数据，覆盖脚本启动、非破坏读取、旧版全文迁移与 ID、收藏显示、搜索、每期档案、ISO 周、日期、安全文本链接与备份验证。不能代替真实浏览器的视觉与点击测试。

v0.3a 已通过隔离 Node VM 自动回归检查；真实浏览器视觉与点击验收请按下方步骤执行。

## 当前限制

- 未连接 ChatGPT 推送、实时学术检索、账号、数据库或自动跨设备同步。
- 所有内置信息均为示例，不代表真实论文、新书或期刊更新。
- 不用 AI 自动拆解周报；研究信息由用户手工添加。旧版全文作为一个条目保留，可后续编辑整理。
- 目录是浮动层，短文不足两个标题时隐藏；没有全文 Markdown、脚注系统或富文本编辑。
- GitHub Pages 部署需包含 `index.html`、`styles.css`、`app.js`、`public-data.js`、`sample.js` 和整个 `data/` 目录。使用相对路径，兼容仓库子路径。线上数据和本地文件数据独立，可用 JSON 迁移。

## v0.3a 公开周报文件

- data/index.json：version 为 1，reports 数组每行包含 id、date（发布日期）、demo（布尔值）、path（data/weekly/文件名.json）。数组顺序不影响展示，按 date 倒序排列。
- data/weekly/2026-W46.json：明确标记的演示数据，不是正式学术发布；参考链接与日期均用于测试，不能引用为学术来源。原 sample.js 与旧演示 ID 保留。
- public-data.js：公开索引、数据校验、网络读取及评价/参考文献安全渲染。

新增一期：复制演示 JSON 为新的周次文件，填写 id、week、startDate、endDate、date、title、summary、body、demo 和 entries。日期使用 YYYY-MM-DD，week 使用 ISO 周（如 2026-W46），发布日期须在该期范围内，起止日期须属于同一 ISO 周。正式数据核实完成后设置 demo: false；测试材料必须保持 demo: true，并在标题、正文及来源中明确标注。

报告 ID 使用 rw-public: 加上永久唯一标识（如 rw-public:2026-W47）；条目 ID 必须以报告 ID 加冒号开头，再加固定后缀。发布后不要因标题修改或排序而更改 ID，避免收藏和阅读链接失效。entries 每条需要 id、title（一句话首页提要）、detail（完整详情）、tags（非空多标签数组），可选 date。references 非空数组每项需要 title、url（原始 HTTP/HTTPS 链接）、publishedAt（实际发表日期）、sourceType。evaluation 需要 contribution、evidence、limitations、basis，分别填写贡献、关键证据、薄弱之处和评价依据。正式文献应使用实际可核实日期，不以抓取日期替代。

随后在索引 reports 中添加相应 id、date、demo、path；元数据必须与文件一致。两份文件一起提交。索引不应重复 ID；不要删除原有周报文件。运行 node check.cjs 后再部署。

公开报告只读，不写入 rw-reports-v1；手动报告、收藏仍用原存储键。主页和档案显示来源标签。同报告 ID 冲突时本地优先，公开版本不重复显示，也不修改原数据；条目 ID 冲突时公开条目在显示层加报告前缀隔离。备份只导出本地报告和所有收藏，公开正文由仓库维护；恢复本地备份仍按原流程确认替换本地资料，不改变仓库内容。读取失败或某期无效时显示持续提示，保留本地与内置演示；单期失败不阻止其他有效周报展示。刷新后重新请求，不提供公开报告的离线缓存。

### 每周配置

保留可选字段 heroImage、heroImageAlt、heroImageCredit、themeColor。新增可选对象 heroImageRights 集中记录版权，不改变原核心周报结构：

```json
{
  "heroImage": "assets/weekly/selected-illustration.webp",
  "heroImageAlt": "说明插画中实际出现的景物。",
  "heroImageCredit": "作者或来源的简短兼容说明",
  "themeColor": "#806b91",
  "heroImageRights": {
    "title": "插画名称",
    "creator": "作者或创作者",
    "source": "作品、馆藏或素材来源",
    "license": "经核实的版权或授权状态及必要声明",
    "method": "手绘、扫描或 AI 辅助制作方式",
    "sourceUrl": "https://example.com/artwork",
    "licenseUrl": "https://example.com/license"
  }
}
```

上述 URL 和名称仅为格式占位，不代表实际来源或许可证。heroImageRights 全部为可选文字字段（各最多 2000 字符）；sourceUrl、licenseUrl 只接受有效 HTTP/HTTPS URL，不接受带用户名密码的链接。来源与许可证链接在「关于本站」中以新标签打开，文字安全转义。对于旧周报，仅填写 heroImageCredit 时仍可在该小节查看原说明；没有记录的项目显示“未记录”。每份记录显示周次、报告标题及 ID，与对应周报关联；同 ID 冲突沿用本地优先规则。公开 JSON 请求失败时只显示当前可读取的记录，不凭空补全版权信息。

将选定图片放入 assets/weekly/ 并与 JSON 一起提交，无需修改索引。支持 SVG、PNG、JPG/JPEG、WebP 和 AVIF，路径相对于网站目录，不带开头斜杠；允许英文字母、数字、连字符和下划线命名的子目录，不接受外站图片 URL、路径穿越或查询参数。SVG 使用可信静态资源。设置图片必须填写非空 heroImageAlt（最多 500 字符）；heroImageCredit 最多 500 字符，只在「关于本站」用作旧格式兼容说明，首页不再显示署名。

使用第三方作品前须核实来源和许可，保留作者、作品名称、版权说明、来源及许可证链接；不能仅因参考图展示在网上就认定公共领域。需要近图署名等特殊条件而集中说明无法满足时，不要选用，或先取得符合本页面展示方式的许可。AI 辅助作品如实记录制作方式，不擅自赋予公共领域或排他版权声明。

themeColor 为可选六位十六进制色，建议柔和且文字可辨。没有指定时继续按 ISO 周轮换。无插画时保留干净淡色背景，不自动生成几何山水。图片按原始比例完整显示（object-fit: contain），不机械拉伸或裁掉画面；宽窗口右侧占位，900px 以下及打开阅读面板时移至文字下方。图片加载失败时隐藏，保留淡色留白，不显示破损图标。
